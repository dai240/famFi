# 夫婦の家計・支払元・定期支出

2026-09-09 合意、2026-09-10 実装・本番反映済み。本人は利用可能。妻の招待と実ログインはメール確認待ちであり、完了に含めない。

## 合意と範囲

- 夫婦別ログインで同じ家計簿を共有し、双方が支出・マスタ・精算を閲覧/作成/編集できる。既存記録も共有する。精算履歴がある支出の削除制限は維持する。
- 家族カードの引落先は家計の共通口座。入金・銀行残高・カード引落管理は後続であり、架空の入金や二重の支出を作らない。
- 新規の支払元は必須、初期値は家族カード。購入者はログイン本人、対象は家族、日付は今日。カテゴリ→金額→内容→支払情報→日付の順。
- 個人払いの初期値は立替。車や年パス等は「直接負担・返金なし」へ変更する。直接負担も家計の支出に含み、共通口座残高を増減させない。
- 購入者、対象、資金の持ち主、記録者を分離する。自分は表示用の別名で、保存するのは安定した人物ID。対象の家族/自分/その他は固定の選択肢。その他の文字列は記録単位で保存し、マスタを自動作成しない。
- 初期人物は夫/妻/家計の共用資金。支払元は家族カード/家計口座/夫と妻それぞれの現金・個人カード・個人口座。食費・日用品・光熱費などの子カテゴリも追加する。
- 定期支出は月払/年払、定額/変動額、開始/終了月、計上日または月のみ、支払元・扱いを保存。月ごとに確認して支出を作成し、自動で実績を作らない。二重確定を防ぎ、当月スキップと取消に対応する。
- ローンは当面返済予定/実績の登録まで。購入額と返済の両方を支出へ自動生成しない。元本/利息・借入残高・返済計画の計算は未対応。
- 家計への入金、複数立替の一括相殺、複数人への配分、自動送金、商品返品、複数明細への分割は今回含めない。

## 権限と移行

- 既存の `user_id` は互換性のため安定した家計IDとして維持する。ログイン本人は `app.user_id`、本人が参加する家計は管理者のみが登録できる `household_members` から解決する。クライアントの家計ID・userId・記録者は信用しない。
- 既存データのID・金額・日付精度・カテゴリ・更新情報を保持し、旧支払情報はlegacyとして扱う。新規は必須、旧記録も編集時には支払元を選択する。既存記録を家族カード/精算不要へ一括変換しない。
- 家計メンバーの追加はAuth本人確認と明示された招待先の確認後に管理作業で行う。人物マスタ追加はログイン権限を作らない。妻のメールが未確認なら人物設定と共有機能まで用意し、招待完了とは報告しない。
- 同一家計の更新を直列化し、バージョン競合を拒否する。変更者と変更前後の履歴を保持し、一般runtimeからの履歴上書き/削除/捏造を拒否する。
- 正本SQLは共有基盤に保存。変更対象はfamfiのみ。共有Auth設定・他アプリの権限を変更しない。

## 支払いの扱い

| 扱い | 条件 | 精算 |
| --- | --- | --- |
| 共通資金 | 共用資金に紐付く支払元 | 不要 |
| 立替 | 個人資金の支払元 | 家計から資金の持ち主へ。初期値は全額 |
| 直接負担 | 個人資金の支払元 | 不要。家計への直接負担額として集計 |
| 精算内容を指定 | 既存の相手/対象額指定を使用 | 家族カードの個人利用などの例外 |
| あとで確認 | 支払元は選択済み、負担ルール未確定 | 未確定として区別 |

設定を保存した後は、再編集やマスタ変更で精算ルールを勝手に再計算しない。新規の候補設定は画面に表示し、利用者が変更可能にする。

## 画面・復旧の扱い

- 支出・立替/精算・定期支出・変更履歴の4画面。支出の一覧とCSVで支払元/扱いを追え、直接負担は支出合計内の内訳として人物別に表示する。
- 定期支出の設定変更は将来の候補にだけ反映し、登録済み実績の金額・日付・支払元を変えない。対象月と実際の支出日は別であり、月末31日は短い月の月末へ寄せる。
- 精算履歴のない定期支出の実績を削除すると、その月は未登録に戻る。精算履歴がある場合は削除を拒否する。削除した実績の変更履歴は残る。
- 予定の停止/終了は過去の実績を消さない。使用停止した設定は「すべての設定」で再編集できる。自動計上・自動支払・自動送金はない。
- v4暗号化バックアップは定期支出・変更履歴も含む。DB変更前後は `node --import tsx scripts/household-migration-check.mjs before|after <直前の暗号化backup>` を使う。beforeは旧v3、afterは既存項目を照合してv4を取得する今回専用の移行検査。日常は `npm run backup -- create <確認済み本人Auth UUID>`。
- v4のローカル復元では全項目・別家計からの拒否を確認する。Authと家計参加者対応表は復旧対象外なので、本人確認を伴う管理手順で別途設定する。詳細は [配偶者ログイン](household-onboarding.md)。

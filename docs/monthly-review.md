# 月の確認事項

2026-09-18。優先順位と残作業は [次のタスク](next-tasks.md)。公開前の実装・検証記録。公開結果は確認後に追記する。

## 実装

- 支出画面に「この月の確認」を追加。初期状態は折りたたみ、当月の確認待ち件数・別月の件数・任意の整理を簡潔に表示する。一覧の絞り込みやページには依存しない。
- 確認開始日を迎えた未確定の定期支出・単発予定を件数へ含める。未来の確認日と延期中は中立表示し、次の確認日を表示。スキップ・確定・中止・停止を催促しない。
- 別の月の確認待ちも月別に表示。定期支出は該当月、単発予定は該当月の予定へ移動する。単発予定の「この月の予定のみ」を解除すると全期間へ戻せる。通常のメニュー起点では従来どおり全期間。
- 精算要否が`unknown`の実支出を「支払情報の確認」に表示し、IDから既存の編集画面へ開く。名称未入力はカテゴリ名。日付/月精度を保持し、保存後に再集計。金額を「返すべき額」と推測しない。
- [サンプル判定](sample-data.md)に該当する支出は確認対象から除外し、除外件数だけ表示。仮の定期設定は通常の仮設定確認を経由し、直接確定を迂回しない。
- 未完了のまとめ記録で残額があるものは「まとめ記録の整理・任意」へ分離。件数バッジに加算しない。明細化済み/まとめ記録で完了は除外。カレンダー表示からも該当するまとめ詳細へ移動できる。
- 60秒ごとの既存バッジ取得を拡張し、月変更・保存・更新・画面復帰で更新。古い月の応答を描画せず、同一effectで取得が重ならないよう制御。取得失敗はエラーと再取得操作を表示し、0件と扱わない。

## 境界

- 既存`GET /api/attention`に任意の`month`を追加。指定なしの`count`/`items`は互換。既存の明細100件上限より前の全件から月別件数を算出するので古い残件で対象月が欠落しない。
- 月指定時だけ必要列の要確認支出と未完了まとめを取得。サーバー認証、`withUserDb`、`scope.ledgerId`、専用runtime、強制RLSを維持。ユーザー/家計IDの指定は拒否。共有Authや資格情報を変更しない。
- 確認欄そのものは読取専用。実際の更新は既存フォーム/APIのバージョン確認・履歴・同時更新制御を通る。予定の自動確定、支払い/送金、架空入金は追加しない。
- 支出合計、CSV、バックアップv7/旧版互換、DB/migration/権限、サンプルや本番データを変更しない。Previewや他アプリも変更しない。

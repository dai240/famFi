## 安全な再実行・撤去

- 投入スクリプトは `scripts/seed-summer-sample.mjs`、架空データ定義は `scripts/sample-summer-data.mjs`。Production schemaと専用role、厳密TLSを明示し、確認済みownerを管理照会で解決する。業務処理は既存withUserDb/withLedgerDbと入力検証・保存serviceを使う。
- 支出/テンプレート/確定履歴IDは家計IDと固定batchキーから決定する。同じ内容の再送は二重保存しない。編集済みのサンプルは上書きせず停止する。途中で止まった場合も、作成済みの状態を確認して再実行する。
- `inspect` は読取のみ。投入には `NODE_ENV=production FAMFI_DB_SCHEMA=famfi node --import tsx scripts/seed-summer-sample.mjs apply --allow-production-sample` を明示する。通常起動・デプロイ・migrationで自動投入しない。投入前後にv7暗号化backupと使い捨てローカルDBへの復元を検証する。
- 将来撤去する場合は、batchの決定ID・メモ・変更履歴を照合し、実データへ編集されていないか確認する。名前の部分一致や7月/8月全体を条件に削除しない。精算済みなどの参照/削除制約を守り、共有DBのreset、履歴の消去、権限の一時拡大は行わない。
- この作業で共有Auth、ログイン権限、Preview、Compath、sateni、DDL、Vercel環境変数は変更しない。アプリの再デプロイは不要。

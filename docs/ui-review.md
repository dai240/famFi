# 日常利用のUI整理

2026-10-07。支出・入出金・サマリー・登録・設定を横断して、必要な情報を残しながらスマホの縦スクロールを減らす。公開の正本は共有基盤repoの `docs/status.md`。

## 支出の最初の画面

- 月選択、登録済み支出合計、カード分の反映状態を先に表示し、その直後に一覧/カレンダーを置く。重複する「家計簿」の見出しと余白を整理する。
- 固定/変動/特別/未分類、前月比較、直接負担、カテゴリ別は「内訳・比較」にまとめ、初期状態では閉じる。月合計はフィルタで変えない。
- 件数を「まとめ」「個別」に分ける。月まとめのみの月は記録済みと表示し、任意の個別内訳がないことを大きな未登録表示にしない。
- 月まとめと個別明細を一覧内にまとめる。個別明細の絞り込みは必要時に開き、適用中を表示する。月まとめは既存どおり絞り込み対象外と明示する。
- 予定・支払いの確認は実際に確認対象があるときに表示する。カード未反映の隣に「確認待ちなし」を並べない。通信失敗は確認済み/0件と扱わない。

## 未反映とゼロの区別

- カード未反映で金額がない場合は、翌月の引落明細待ちとして中立表示する。未確認額ありは黄色系、確認済みは既存の完了表示を維持する。
- 未記録・カード未確認の月を支出ゼロ確定とみなし、前月比-100%を出さない。記録がある未確認月は「登録済み額の差」として差額だけを表示する。
- 割合は両月のカード確認が済んだ過去月同士で、前月額が0より大きい場合だけ表示する。当月/将来月は従来どおり割合を出さない。カード確認は家計のすべての記録が網羅された保証ではない。
- 明示的にカード確認した0円の月は比較可能。確認操作のAPI、銀行原本、まとめ計上、任意内訳、月のずらし方は変更しない。

## 共通の操作

- スマホのボトムナビは「支出 / サマリー / 新規支出 / 予定・定期 / メニュー」。立替・精算はメニューへ移し、機能は維持する。中央の登録と、取消後に元画面へ戻る動作を保持する。
- サマリーの期間/月を横並びにし、共通銀行口座が1件なら選択欄ではなく名称を表示する。複数口座は選択でき、使用停止の表示も保持する。
- 入出金のCSV取込は見出し横の専用ボタンへ移す。定期支出も共通のコンパクトな見出し/余白を使う。確認日前・確認待ち・登録済み・スキップの区別は変えない。
- 新規支出の「費用区分・メモ」は必要時に開く。現在の区分とメモの有無を閉じた状態でも示す。支払元・本人・家族・今日の既定値、必須項目、精算方向を保持する。既存編集と定期の詳細編集では追加欄を開く。
- カレンダーの「月まとめ・日付未定」は日別のマスより上へ移す。実日付を推定せず、月だけの明細・共有メモ・予定を確認できる。
- 設定画面は「家計の設定」、スマホの入口は「カテゴリ・支払元の設定」。カテゴリの子階層は親単位で開閉する。色、並び順、停止、人物の固定権限は保持する。

## 境界

DB構造、migration、共有Auth、環境変数、参加者、支払いの既定値、既存データ、CSV計算、v9 backupは変更しない。`/api/expenses` のまとめ件数と既存の比較APIのカード確認状態だけを追加し、既存 `withUserDb` の家計隔離内で読み取る。銀行原本を新たな支出・入金・返金に変換しない。

実銀行CSVや本人データをローカルfixture/Previewへ移さない。本番確認は既存セッションでの読み取りに限定し、実支出・精算・カード確認を保存しない。

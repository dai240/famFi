# カテゴリ・人物・支払元・立替精算

2026-09-09実装。最初のゴールである支出入力を維持し、追加情報は任意とする。本番反映の確認記録は末尾と共有基盤の状態文書を参照。

## 今回の範囲

- マスタ管理: カテゴリの追加、名称・色変更、親子2段、並べ替え、使用停止と再開。過去に使ったマスタは削除しない。
- 人物と共用資金のマスタ: 自分・家族などの人物と、家計の共用資金を登録する。Authアカウントや共同編集権限の追加ではない。
- 支払元マスタ: 個人/共用カード、現金、口座・振込、電子マネー等。名称・方法・資金の持ち主を管理する。カード番号や金融機関の資格情報は保存しない。
- 任意の支出詳細: 使った人、誰のため、支払者・資金の負担元、具体的な支払元。支払元の持ち主を候補として選択し、選択値を表示して変更可能にする。
- 精算要否: 未設定・あとで確認、精算不要、立替・精算が必要。既存支出を勝手に本人・共用・精算不要扱いにしない。
- 立替: 1支出につき「返す側 → 受け取る側」1組と精算対象額を明示。対象額は購入額以下の正の整数。全額ボタンは本人の操作でのみ適用する。
- 精算: 全期間の未精算一覧、方向別残額、未精算/一部精算/精算済み、精算日・金額・メモ、取消と履歴。部分返金と複数回の返金を扱う。
- 入力支援: 詳細欄の開閉、入力途中のマスタ管理、編集中の破棄確認、支出の複製、内容・メモ検索、人物・支払元・精算状態での絞り込み。
- 支出CSV: 親子名・人物・支払元・精算状態/対象額/残額を追加。月別・全期間・絞り込み結果を出力する。精算履歴は別CSVにID・支出との関連・取消日時を含める。

最初に人物や支払元を作らなくても、金額・日付/年月・カテゴリだけで保存できる。既定の人物や負担ルールを認証アカウントから推測しない。

## お金と履歴のルール

- 購入時だけ支出合計へ加算する。立替の返金は精算記録であり、支出や収入へ二重計上しない。月のみの購入と実際の精算日も分ける。
- 未精算額 = 精算対象額 - 有効な精算記録の合計。取消済みの精算は合計から除き、履歴には残す。
- 精算記録は上書きしない。訂正は取消後に正しい内容で再登録する。
- 有効な精算がある支出の金額・支払元・精算相手/対象額は変更不可。先に精算を取り消す。内容・メモなどの訂正は可能。
- 取消を含め精算履歴がある支出は削除不可。支出との関連を残して訂正する。取消後に精算不要へ訂正した場合も、元の精算相手は履歴に残る。
- 複製は新しい支出IDで作成し、精算済み額と精算履歴は複製しない。既存支出・マスタ・精算は安定したIDで関連付ける。
- アプリの短い更新トランザクションを利用者ごとに直列化する。精算時は支出行をロックし、バージョン確認と過払い制約を適用する。再送は同じUUIDを使い、同一記録を重複保存しない。

## 今回含めないもの

- 複数支出を一度に処理する一括精算、1支出の複数人への負担配分、自動折半・自動相殺。
- 銀行からの自動送金、カード決済・引落しの実行、カード明細の取込。実際に返金した結果を記録する機能であり、送金機能ではない。
- 固定費・テンプレート・保存して次へ、家族の複数アカウント共同編集、収入・予算、レシート/OCR。複製・検索は今回先行した。
- 返品・返金による購入額自体のマイナス訂正。立替の返金と商品返品は別機能。

## DBと互換性

- 正本SQLは `personal-apps-infra` の `famfi_expense_management` migration。famFi以外のスキーマ・Auth設定・資格情報は変更しない。
- `famfi.categories` の固定10件は初期テンプレートとして維持する。編集対象は利用者別の `famfi.category_entries`。既存のカテゴリID、支出のID・金額・日付精度・メモ・更新情報を維持して、利用者別カテゴリへの複合外部キーへ切り替える。
- 現在のmembershipごとにカテゴリをコピーし、今後のmembership作成時もfamFi内のinvoker triggerで初期カテゴリを作成する。一般runtimeにはmembership作成権限を与えない。
- 新しい `parties`、`payment_sources`、`settlements` とカテゴリ管理テーブルにRLSを強制する。同じ所有者の人物・支払元・カテゴリだけを参照できる複合FKを使う。
- カテゴリ・人物・支払元は利用者単位。人物マスタを追加しても他アプリや家族アカウントへのアクセスは増えない。
- 新しい情報の記録開始後は、対応前のデプロイへ戻さない。古い画面から詳細情報を消す更新は409で拒否する。開いたままの画面は更新する。
- バックアップv3はカテゴリ、人物、支払元、支出、精算を含む。v1/v2もローカル復元可能で、旧情報は未設定・精算額0として移行する。

## 検証

- 単体/移行/暗号化復元16テスト。このうち追加DB検証は47項目。既存DB検証34項目も維持。
- Next API + 独立PostgreSQL 17.6: 既存API63、新API188項目。同時精算は201と409に分かれ、二重精算しない。
- Chromium/WebKitそれぞれ320x700、390x844、430x932、390x600、844x390、1280x900。新しいマスタ・支出・一部精算・取消・CSVの314項目と、従来の日付/色/支出CRUDの182項目。
- 簡易PGliteは複数接続を通常のPostgreSQLと同等には扱わない。同時実行検証は `FAMFI_TEST_PG_BIN=/absolute/path/to/bin npm run test:stack` で独立した使い捨てPostgreSQLを起動して実施する。起動先はloopbackのみで本番環境変数を上書きし、終了時に削除する。
- 本番適用前にv2暗号化snapshotを再取得。適用後は専用runtimeで既存項目照合とロールバック付き書込み検査を行い、v3暗号化snapshotを空のローカルDBへ復元して照合する。実記録をテスト用に削除・復元しない。

本番の適用・公開状態は基盤 `docs/status.md` を正本とする。実機iPhoneでの再確認、鍵とbackupの別保存先、自動バックアップは引き続き残作業。

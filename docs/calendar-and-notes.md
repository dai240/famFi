# 家計の共有・カレンダー・共有メモ

2026-09-10実装。本番公開の結果は末尾に追記する。コード実装と公開確認を区別する。

## 共有の境界

- 家計ごとにSupabase projectやschemaは作らない。famFiの同じテーブルを家計IDと強制RLSで分ける。別アプリ・本番/Previewのschemaと専用roleは既存のまま。
- ログインだけでは利用できない。サーバーが実ユーザー、active membership、household_membersを確認する。今回も一般自己登録・参加権限の自己付与は開けない。
- メニューの「家計の共有」で家計名と参加状況を表示する。人物マスタ上の妻が存在しても、ログイン未設定なら参加中と表示しない。参加解除・招待・家計の作成申請UIは今回追加しない。
- household_roster() は既存member_self RLSを拡張せず、同じ家計のparty_idとactiveだけを返す限定的なread-only SECURITY DEFINER。空のsearch_path、固定schema、実actorのactive membershipとledger一致を明示確認し、Auth UUIDやメールは返さない。public/anon/authenticated/service_roleからEXECUTEを剥奪。runtimeにメンバー変更権限は与えない。
- 妻のメールは未確認。実メールでの招待とログインは [参加手順](household-onboarding.md) に沿う別工程。一般登録を開く・共有SMTPを変える・他アプリへ権限を付ける作業は含まない。
- 将来の家計作成申請、owner/member権限、期限付き/一回限り/宛先固定の招待承諾、招待取消・最後の管理者保護は未実装。夫/妻のsystem_keyを管理者権限として流用しない。

## カレンダー

- 支出画面の「一覧 / カレンダー」切替。既存の支出・単発予定・未確定の定期支出と日付付き共有メモを表示する。日を選んで明細を開く。支出は既存編集、予定/定期は同じ月の予定画面、メモは編集へ進む。
- 日付を選んだ追加ボタンのみその日/月を初期値にする。中央の+は引き続き今日・家族カード・本人・家族が初期値。
- 月のみの支出/予定/メモとまとめ記録の残額は「日付未定・月のみ」欄へ置き、1日の支出へ偽装しない。日付なしメモは共有メモ一覧に置く。
- 合計は実績＋まとめ記録の未整理残額だけ。紐づく実績の二重計上をせず、月をまたぐ関連も従来の計上月を維持。予定・定期・メモは実績へ加算しない。
- 固定額でない定期の予定額は金額未定。前回金額は確定フォームで従来どおり扱う。確定済み/スキップ/停止の予定を実績と重複表示しない。
- カレンダーは月全体。支出一覧の絞り込みは一覧に戻れば保持されるがカレンダーには適用しない。月の支出が10,000件を超える場合は欠落した集計を出さず一覧利用を促す。

## 共有メモ・チェック

- 独立したメモを件名120文字、本文4,000文字、日/月/日付なしで保存する。「完了チェックを付ける」を選べば未完了/完了を切り替えられる。個人専用の非公開メモではなく、家計の参加者に共有する。
- 通常メモに期限超過・催促はない。チェック付きだけ期限翌日以降に黄色い文字を表示。月指定は翌月から。既存の支出確認待ちバッジと混ぜず、メール/Push/自動完了は行わない。
- 買う予定は既存の支出予定を使う。チェック完了で支出・精算・入金を自動生成しない。
- 同一家計でCRUD・検索・種類/完了状態の絞り込み・50件ページング・全件CSV出力。家計ごと5,000件上限。保存失敗は入力を保持。409は最新版を明示的に読み直す。削除は確認を挟み変更履歴に残る。
- 金額やメモをlocalStorageへ保存しない。APIはno-store、書込みはOrigin確認。UUIDの再送は同じ内容のみ許可、更新versionと家計ロックで夫婦の競合を拒否する。

## 日々の入力

- 内容未入力の行ではカテゴリ名を繰り返さず、親/子の名称と色、購入者・支払元・立替状態を表示する。
- まとめ記録がない月は大きな空セクションを作らず追加ボタンに縮める。
- 通常の新規入力に「保存後も続けて登録」を追加。次の行は日付とカテゴリを引き継ぎ、金額・内容・メモをクリア。支払元/購入者/対象/扱いは家計の初期値へ戻し、前の個人立替等を無意識に連鎖させない。確認チェックは連続入力中維持。確定/まとめ明細/編集では表示しない。
- カテゴリマスタの「初期区分を設定」は未設定かつ既知の名称/親カテゴリだけを対象にし、変更内容を確認して保存する。個別設定済みや名称変更済みを上書きせず、過去支出・定期設定を再分類しない。交通/その他など曖昧な親は未分類のまま。UIを開いただけでは自動変更しない。

## DB・復旧

- 正本SQLは基盤のfamfi_notes。famfi / famfi_previewそれぞれのhousehold_notesと限定roster関数、auditの許可対象だけを追加。既存の台帳・Auth・他アプリ・既存支出の値は変更しない。
- 通常INSERTでmetadata列を送らず、限定runtimeの権限を維持。メモの移動や別家計の参照は禁止。
- 暗号化バックアップv7は全v6項目とメモの日付精度/完了/本文/version/日時/履歴を含む。v1〜v6のローカル復元も維持。Auth・参加対応表は従来どおり本人確認を伴う別復旧。
- 本番/Previewは別の資格情報・保管先・鍵。今回専用 `FAMFI_DB_SCHEMA=famfi|famfi_preview node --import tsx scripts/notes-release-check.mjs before|after [直前backup]` でv6→v7を検証する。日常バックアップは既存backupコマンドがv7を自動判定する。

## 残る機能

家計作成/招待の自己操作、個人だけのメモ、複数チェックリスト/担当者、外部カレンダー連携・通知は未実装。家計の入金/残高/引落、一括精算、CSV取込、レシートOCRも後続。日常支出入力と夫婦での実利用を優先する。

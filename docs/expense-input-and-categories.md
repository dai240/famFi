# 支出の日付・カテゴリの仕様

## 現在のカテゴリ選択

2026-09-10の要望に合わせ、親子が混ざった長い一覧から「カテゴリ」「詳細カテゴリ」の2つのプルダウンへ変更する。以下が今回の実装仕様であり、下段の初回MVPは履歴として扱う。本番への適用結果は検証後に末尾へ記録する。

- カテゴリでは親だけを選ぶ。詳細カテゴリは選択した親の子だけを表示し、入力フォームでは「指定なし」を初期値にする。子がなければ詳細欄を出さない。
- 親だけでも登録可能。保存するcategoryIdは従来どおり1つで、子が選ばれていれば子のID、指定なしなら親のID。DB・API形式・既存データの変更や移行は不要。
- 親を変えたら詳細は指定なしへ戻す。編集・複製・定期設定・月別確定では、保存済みのcategoryIdから親と子を復元する。独立した親/子の下書きstateは持たず、マスタ更新後も現在の親子関係を使う。
- 親/子それぞれの色と名称を選択肢・選択後に表示。長い候補名は折り返し、スマホでも画面外へはみ出さない。2つの欄は縦配置、保存footerは固定を維持する。
- 使用停止した親/子は新規候補から除外するが、既存記録で選ばれている場合は表示を保持する。停止した親の子を編集中に「指定なし」へ変えて、使用できない親を新たに選ぶことはできない。
- 一覧では親を選ぶと親自身と子すべてを含める。詳細を指定した場合だけその子へ絞る。詳細の「すべての詳細カテゴリ」は親全体へ戻り、「すべてのカテゴリ」は両方を解除する。
- 過去の記録を探せるよう、絞り込みでは使用停止カテゴリも選べる。絞り込み合計とCSVにも同じcategoryIdを渡し、CSVの名称は従来の「親 / 子」を維持する。

## 日付指定と月のみ

2026-09-09の本人要望: 日を覚えていなくても「2026年9月」の支出として記録したい。

- 入力は「日付指定」「月のみ」の切り替え。月のみから日付指定へ変えるとき、未知の日を1日で自動補完しない。
- APIの `date` は日付指定なら `YYYY-MM-DD`、月のみなら `YYYY-MM`。どちらも2000年から2099年まで。
- DBは `famfi.expenses.date_precision` の `day / month` で区別する。月のみの場合の `date` は集計用に月初日を保存するが、利用者に確定した1日として表示しない。
- 一覧・編集・削除確認で月のみを明示する。月別合計・カテゴリ別合計には通常の支出と同様に含める。
- CSVの日付は同じ精度で出力し、末尾に「日付の精度」列を追加する。表計算ソフトが年月を日付へ変換しても「月のみ」で区別できる。
- 日付精度を追加したバックアップ形式は `famfi-expenses/v2`。現在のv4にも `datePrecision` を保持する。旧v1の精度なし記録は日付指定として復元できる。最新の範囲は [夫婦の家計](household-workflow.md) を参照。
- 正本SQLは共有基盤の `famfi_expense_date_precision`。Auth、他アプリ、既存のカテゴリ構成は変更しない。

## 初期のカテゴリ計画

親子カテゴリは廃止ではなく、利用開始後の次候補として扱う。今回の日付・表示修正には階層DB化を混ぜない。

後続対応でカテゴリマスタ・親子2段・色変更を実装した。上記は日付修正時点の履歴。現在の動作は [支出管理の追加仕様](expense-management.md)、全体の順序は [支出管理ロードマップ](expense-roadmap.md) を参照。

1. 親カテゴリだけでも記録でき、任意で子カテゴリを指定する二段構成にする。
2. 子は文字列ではなく安定したIDを持ち、親との整合性をDB制約で保証する。親の集計は子の支出も含む。
3. 既存の固定カテゴリIDと支出を保持し、未分類の子を勝手に推定しない。旧サンプルのカテゴリをそのまま本番へ流し込まない。
4. カテゴリの追加・名称/色編集・並べ替え・使用停止、親子の絞り込み、CSV・バックアップまでまとめて設計する。利用済みカテゴリの削除で過去の記録を失わせない。
5. 個人・将来の家族共有での所有範囲と編集権限を決め、共有基盤にSQLと権限テストを登録してから公開する。

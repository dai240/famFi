2026-09-10。`preview` ブランチの追加実装。本番 `main` / `famfi-nu.vercel.app` の機能・DBはまだ切り替えない。妻の実メールログインは未完了。

## 入力を続けられる形

| 記録 | 支出合計 | 確認待ち |
| --- | --- | --- |
| 通常の支出 | 登録額を計上 | なし |
| 定期の設定・単発予定 | 未確定なので計上しない | 確認日になった未確定分だけ |
| まとめ記録 | 明細化されていない残額だけを加算 | 催促しない。まとめたまま完了も可 |
| まとめ記録に紐づく明細 | 通常の支出として計上。同額だけ未整理残額を減らす | なし |

### 定期支出

- 月ごとに本人/妻が金額を確認して実績を作る。基準額、前回の確定額、毎回入力を選べる。どの初期値もその月だけ変更でき、過去の実績・基準額へ逆反映しない。前回実績がなければ空欄で必須入力。
- 毎月、2か月ごと、毎年。開始/終了月と計上日/月のみは従来どおり。水道の2か月周期にも対応。
- 確認開始は任意の当月/翌月/翌々月の1〜31日。31日は短い月の末日。未指定は対象月1日。実際の支出日・引落日とは別。
- 確認日前は一覧で「確認日前」、件数バッジには含めない。確認日以降は黄色の件数。過去月の未確定分も残す。赤色の警告・メール・Push・自動確定はしない。
- 確認を後日に延期できる。スキップ/停止/登録済みは催促対象外。過去の確定・取消履歴は保持し、同時操作/再送で支出を二重作成しない。

### 費用の区分

- 固定費 / 変動費 / 特別費 / 未分類。金額の変動や登録周期とは独立。例えば毎月変わる電気代も固定費として扱える。
- カテゴリマスタで新規入力の初期値を選べる。確定する支出/定期設定にも保存し、過去の支出をマスタ変更で自動再分類しない。旧記録は未分類を維持する。
- 月別内訳、フィルタ、CSV、変更履歴、バックアップに対応。比較グラフは未実装。

### 単発予定

- 誕生日プレゼントなどの名称と予定日/予定月を登録。予定額・カテゴリ・支払元・メモ・確認開始日は任意。実績の必須項目は確定時に入力する。
- 既定の確認開始は日付指定なら翌日、月のみなら翌月1日。指定した確認開始日や延期日まで件数へ含めない。
- 確定時は予定額を候補にした通常の支出フォーム。ログイン本人/家族/既定支払元を候補にし、個人の支払元なら全額立替を候補表示する。
- 登録済みの支出へ紐づけることも可能。中止/中止取消、確認延期、確定済み表示に対応。実績削除で予定は未確定へ戻る。精算済み実績の削除制限は維持。
- 1支出を複数予定や定期実績へ重複確定させない。複数支出に分けて一つの予定を消化する機能は未実装。

### まとめ記録

- 細かく入力できない月は、家計の支出分を支払元・計上月・総額で登録。同一家計/支払元/月に一つ。「今回はまとめ記録で完了」なら明細化を要求しない。
- **カード請求の全額を無条件に費用扱いしない。** 個人利用、返金、以前入力した購入、ローン元本や引落の重複を含めないよう、家計の対象額を入力する。これはカード決済/銀行引落の管理機能ではない。
- 既存明細とは「登録済みから」で明示的に紐づける。金額・月が似ているだけで自動照合しない。まとめ記録を作るだけでは、既存の未紐づけ支出は差し引かれない。
- 例: 総額10万円、紐づく明細3万円なら未整理7万円。集計は明細3万円+未整理7万円。明細の追加/編集/削除で残額を再計算し、超過・異なる支払元をDB/API双方で拒否する。
- 明細は実際の支出月、残額はまとめ記録の計上月。月をまたぐ紐づけ/編集は月別合計が動くため確認を求める。総額の計上月変更にも確認を表示する。
- 未整理残額は「未分類」で計上。購入者・精算先を推測せず、未精算額や直接負担へ自動加算しない。個人カード分の立替把握には該当明細を入力する必要がある。
- 解除すると明細は残り、未整理残額が増える旨を確認する。明細のあるまとめ記録は削除不可。CSVは総額行ではなく未整理残額行を出力するので、合算しても二重にならない。
- 他家計拒否、同時更新409、変更履歴を維持する。CSV取込/自動照合/請求締日/残高管理は未実装。

## Previewの境界

- 同じSupabase project `fpptihhtyhehpjvmtuqt` 内の `famfi_preview`。専用の `famfi_preview_app` LOGINが `famfi_preview_runtime` を継承する。強制RLS、アプリ参加者検証、厳密なTLSを本番同様に適用。本番/Compath/Auth台帳への参照とDDLは拒否する。
- 本番からコピーしたのはレビュー済みDDLの構造だけ。実支出・カテゴリ変更・ニックネーム等の本番データはコピーしない。既存の確認済み本人Authを再利用し、独立した空の検証家計と初期マスタを用意した。
- Authユーザー台帳、配信上限、project容量/負荷/停止は共有される。スキーマ分離は完全に独立したSupabase projectの代わりではない。共有Authの削除/設定変更やDB全体resetは禁止。
- `FAMFI_DB_SCHEMA` は `famfi` / `famfi_preview` のallowlist。`npm run generate` で環境別クライアントを作り、ビルド時/実行時の一致を確認。Previewは信頼する `preview` ブランチだけ。任意PRへ資格情報を渡さない。
- Vercelプロジェクトは既存famfiを使用。GitHub連携が未接続のためbranch限定project envを使えず、`scripts/deploy-preview.mjs` が**一つの手動Preview deploymentだけ**へ環境設定を渡す。秘密値はCLI引数/ログへ出さず、Git外の`.env.preview.local`から子プロセス環境に渡す。project全体のPreview envは空のまま。
- `scripts/configure-preview.mjs` は確認済み本人を管理APIで照合してローカル設定を一度だけ作る。既存ファイルを上書きしない。管理トークンをruntimeへ渡さない。
- 妻を追加するときは実メールを確認し、同じAuthを必要に応じて再利用して**Previewの**既存家計のpartnerへ紐づける。本番参加は別の明示的な管理作業。人物マスタだけではログイン権限は増えない。

## バックアップと公開手順

- Previewはv6暗号化バックアップで費用区分・まとめ/明細・予定・確認日・延期を保持。`~/.local/share/famfi-preview-backups/` と専用鍵を使用。本番v5の保存先・鍵とは別。v1〜v5のローカル復元も維持する。
- v6復元は空の使い捨てローカルDBで全項目と他家計拒否を検証する。Auth/参加者/資格情報はバックアップ対象外。リモート全体の復元は実行しない。
- Preview公開: ローカル/API/ブラウザ/復元/ビルドの検証後、`preview` をcommit/pushして `node scripts/deploy-preview.mjs`。READYを確認して検証専用aliasだけを割り当てる。Production aliasは触らない。
- **Preview deploymentをProductionへpromoteしない。** Previewの生成済みPrisma・環境設定を含むため。本番へ進める際は直前のv5バックアップ/復元、正本SQLのfamfi向けレビュー・適用、既存データ照合、famfi向け再ビルド、ドメイン未切替のProduction検証を経て切り替える。
- 妻のメール・実機確認、定期バックアップの頻度/別保存先、共通口座の入金/引落、一括精算/相殺、取込/グラフは残作業。

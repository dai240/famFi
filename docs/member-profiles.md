# 本人確認・表示名と支払元

2026-09-10の合意に基づく実装。公開結果は末尾へ記録する。妻の招待・実メールログインはこの作業に含めない。

## 利用者の確認

- 夫婦は別のログインを使う。管理者が設定した `household_members.party_id` と本人の対応を維持する。初回画面で夫/妻を選んで権限を取得したり、別人へ切り替えたりする仕組みではない。
- 初回表示時に「あなた: 夫/妻」と表示名を確認する。初期値は夫/妻。そのままでも開始でき、表示名は1〜10文字（Unicodeコードポイント数）。空白だけ、制御文字、固定の家族/自分/その他/共通、配偶者側の役割名、家計内の重複表示名は拒否する。
- 本人が違う場合は保存を止め、別アカウントへのログインまたは招待側での紐づけ確認へ戻る。アプリ内から人物IDやAuth対応表を変更しない。
- 初回確認はDBに保存し、別端末・再ログインでも繰り返さない。初回済みでもヘッダーの名前や人物マスタの自分から表示名を変更できる。夫/妻/共用資金の固定項目そのものの改名・種類変更・使用停止は引き続き不可。
- 表示名はfamfi専用の `parties.nickname`。共有Authのプロフィールや他アプリの表示名は変更しない。本人だけが自分の表示名を更新でき、配偶者は参照できるが変更できない。
- `PUT /api/profile` は名前と更新versionのみを受け取る。人物ID・家計ID・userId・役割は受け付けない。サーバー認証、同一家計ロック、更新競合確認、DB側の本人チェックを維持する。初回確認は表示設定であって、家計アクセス権の代わりではない。
- 保存失敗・競合時は入力を保持する。競合時には最新versionを明示的に読み込み、入力中の名前で再保存できる。

## 支払元

- 日常の選択は1つのプルダウン。共通→ログイン本人→配偶者/その他の人物でグループ化する。新規支出は引き続き家族カードが初期値。
- 個人の支払元は安定した資金の持ち主IDと識別名 `owner_label` から「表示名のカード/現金/口座」等を組み立てる。ニックネームを変えても過去の支払元ID・資金の持ち主・精算相手は変わらない。
- 初期登録された夫/妻それぞれの現金・カード・口座は連動する。移行で一致するのは固定人物ID、支払方法、元の完全一致の名称を持つものだけ。独自に付けた名前は推測で書き換えない。
- マスタの入力順は資金の持ち主→支払方法→識別名/名称。個人は「持ち主の名前を付ける」が初期値で、表示結果を確認できる。独自の完全な名称を使う場合は解除できる。共通の支払元は従来の名称を維持する。
- 識別名は40文字まで。連動する識別名の重複は同じ持ち主の中で拒否し、夫婦それぞれに「カード」を登録することは可能。連動しない名称の重複は家計全体で拒否する。APIでも現在の表示名が重複しないか確認する。本人の表示名・追加人物マスタの改名で連動先が別の支払元と同名になる場合も保存せず、元の名前を保持する。
- 元の `payment_sources.name` は互換用に保持し、移行で書き換えない。新しく連動登録する場合は識別名を保存する。各画面・CSVはサーバーで解決した表示名を使う。識別名の保存と表示名の文字列置換を混同しない。
- 使用停止した支払元は新規候補から除外するが、選択済みの旧記録や絞り込みでは表示する。

## 支出の意味は変えない

購入・支払いをした人はログイン本人、対象は家族、日付は今日が初期値。「自分」は入力中の補助表示のみで、一覧・精算・CSVには人物の具体的な表示名を使う。

例えば夫が妻のカードで家族の買物をした場合、購入者は夫・対象は家族・支払元と資金は妻・立替の返金先は妻。表示名の変更でこの対応や金額・精算状態を再計算しない。

## 履歴と復旧

- 表示名・初回確認・支払元の識別名の変更も、既存の変更履歴に実際の変更者と前後の値を記録する。履歴の過去の値を新しい名前へ一括書き換えない。
- v5暗号化バックアップに `nickname` / `profileConfirmed` / `ownerLabel` を追加する。v1〜v4の復号・ローカル復元を維持する。Auth・家計参加の再設定は引き続き管理者の別作業。
- 正本SQLは共有基盤の `famfi_member_profiles`。適用前は `scripts/profile-migration-check.mjs before <直前v4 backup>`、適用後は `after <beforeの出力>` で旧全項目を照合し、v5暗号化snapshot・ローカル復元・ROLLBACK付きruntime検査を行う。このスクリプトは今回の移行専用。
- 共有Auth、環境変数、他アプリのschema/roleには変更しない。nicknameを使って人物やログイン権限を再検索・再割当しない。

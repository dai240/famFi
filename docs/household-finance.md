# 月次の家計管理

2026-10-05の合意に基づく実装。公開状況は共有基盤の `docs/status.md` が正本。

## 運用

1. 「入出金」の楽天銀行CSV取込で、共通口座と期間を確認して取り込む。CSVはサーバーで解析し、口座残高・原本ファイルを保存しない。重複・削除済み明細は再登録しない。
2. 「カード引落の支出計上」で翌月のカード引落を選び、前月のまとめ支出へ計上する。例: 10月末引落は9月の支出。2枚とも家計用という合意に基づき、購入者は推定せず、同じ家族カード・月の合計にまとめる。
3. 2枚分がそろったことを本人が確認して、支出画面の「楽天カード分」を確認済みにする。未取込の月を支出ゼロ・確定と扱わない。内訳は任意。追加計上・解除で金額が変われば確認待ちに戻る。
4. カード以外の家計支出は通常の支出登録。個人の現金・口座・カードの初期設定は「直接負担・返金なし」。妻の住宅ローン・光熱費、夫婦どちらが払った保育費も同じ扱い。定期支出は毎月手動で金額を確認して確定する。
5. 共通口座への入金は入出金として記録する。CSV側で人物不明の入金は、確認できた場合だけ「家計への入金」と人物を設定する。手入力と同じ口座・日付・金額の銀行明細は、本人の確認後に照合し、手入力側を集計対象外にする。

銀行明細は原本の取引記録であり、直接の買い物・返金・預金残高ではない。カード引落から支出を作るのは上記の明示操作だけ。他の出金・入金を自動で支出や精算にしない。明細の口座・日付・金額と重複防止キーは変更不可。

## 内訳と二重計上

- 銀行由来のまとめ額は、対応する銀行出金の合計。画面から金額・計上月・カードを直接書き換えない。変更は入出金から紐づけ解除して行う。
- 内訳を追加しても支出合計は増やさない。合計は内訳実績と未配分残額。登録済みの同じ月・カードの支出があれば、内訳に含めるか、別の支出であることを明示確認する。
- 内訳の実際の購入日を保存し、集計・カレンダー・前月比較はまとめ記録の計上月へ寄せる。実日付と計上月はCSVにも残す。銀行引落の前月というルールは会計上の厳密な購入月判定ではなく、この家計の継続しやすい運用ルール。
- 引落を解除する際、内訳額を下回る変更は拒否する。先に内訳を整理する。解除しても銀行原本は消えない。

## 負担と貸し借り

「メニュー → 負担・個人の貸し借り」で以下を分けて表示する。

| 記録 | 家計支出 | 人物別の家計負担 | 返済待ち |
| --- | --- | --- | --- |
| 夫が共通口座へ入金 | 増えない | 夫の入金額 | なし |
| 妻の口座から住宅ローン | 増える | 妻の直接負担額 | なし |
| 共通カードの引落を前月計上 | 前月に増える | 増えない | なし |
| 妻の家計用立替を例外登録 | 購入時に増える | 未精算部分は未確定 | 家計から妻へ |
| その立替を夫の現金で返金 | 増えない | 夫が返した額 | 減る |
| その立替を共通口座から返金 | 増えない | 個人負担は増えない | 減る |
| 立替の残額を妻の負担に変更 | 増えない | 妻の負担額 | 減る |
| 夫の私物を妻が払い、後日夫が返す | 対象外 | 対象外 | 個人間の貸し借り |

家計負担は「確認済みの入金 + 直接負担 + 個人資金から実際に返金した額」。不明な入金は確認待ちとして別枠。半額精算・公平性の判定・口座残高・自動送金は行わない。未精算の立替を勝手に個人負担へ移さない。

精算では返金元を必須選択し、一部返金・取消を履歴付きで扱う。「返金せず元の支払者の家計負担にする」は架空の入金や現金移動を作らない。個人間の貸し借りは別台帳で、一部返済・返済元・返済日・取消を保存する。返済履歴があれば金額・当事者の変更や元記録の削除を拒否する。

## データと権限

- 正本SQL: 基盤repoの `famfi_household_finance`。本番 `famfi` と隔離済み `famfi_preview` のみ。Previewでは実銀行CSV取込APIを無効化する。
- 専用runtime、server-verified Auth、家計RLS、業務列だけのINSERT、同一家計のロック、楽観的versionを維持。家計ID・記録者・内訳の計上月をクライアントから受け付けない。
- まとめbasis、内訳計上月、銀行リンク・照合、精算元、月の確認、個人債務・返済をv9暗号化backup/履歴に保持。v1-v8も独立ローカルDBで復元可能。共有Auth・参加設定は別の管理手順。
- 本番DDL前後: `NODE_ENV=production FAMFI_DB_SCHEMA=famfi node --import tsx scripts/finance-release-check.mjs before|after <直前v8backup>`。Previewはschemaだけ切り替え、別鍵・別保存先を使用する。
- 既存の本人承認済み64銀行明細だけの移行は `post-reviewed-bank-expenses.mjs prepare` → 内容・backup確認 → `apply <backup> --allow-production-post`。通常の月次取込には使わない。原本、他の記録、既存履歴を保全する。

## 残る運用

- 妻の招待・実メールログインは、メール確認と既存家計への明示参加設定が必要。
- ローン等の実際の定期設定は本人が入力する。削除済みサンプルを復活させない。
- バックアップの定期実行・別保管先は未設定。個人別負担のCSVと債務CSVは復旧用backupの代わりではない。
- 支出計上は確認付き手動操作。銀行・カードAPIとの自動連携、カードの購入明細CSV、自動分類、口座残高管理は対象外。
